| --- | ---: | ---: |
| 真实主副标题 | 148 / 148 | 148 / 148 |
| 构造边界 | 263 / 337 | 337 / 337 |
| 说明文字变体 | 9,099 / 9,515 | 9,515 / 9,515 |

490 组改善共享若干规则根因，并非 490 个独立 bug，也不代表全站准确率：

- 主标题确定的季集保持优先，副标题按缺失字段补充，不将单集和整季描述拼接。
- “第二季 全24集”可同时补季与集数；同类编号按出现顺序取值，“第08集”优先于日文别名里的“第2期”。
- 范围支持 `- ~ ～ – — 至`；拒绝倒序、零起始范围与越界数字；`13-24Fin` 正确计算为 12 集。
- 类型/演员/剧情/备注字段、更新计划和其他季度说明不污染当前资源；后续独立字段中的“全24集”仍可读取。
- “非 DIY / No DIY”不再增加 DIY 属性，肯定的 DIY 标记仍可识别。
- 拼音标题补中文名时排除简繁字幕、国语中字及季集等说明；保留副标题原文。
- Python 回退同步修复，补齐 PT 年度季号的四位数字读取，避免 `S2026` 截断为 `S202`。

这是确定格式的解析，不解析任意自然语言，也不推断播出计划等于实际收录内容。无额外上下文的“共24集”延续既有总集数约定；带“预计/计划/播出进度”等说明时不补入资源集数。

Rust 仓库的 `subtitle_samples.json` 保存原始记录和边界案例，`scripts/build_subtitle_corpus.py` 只读取独立标注并追加说明，不导入解析器、不按通过率选样。未确定电影类型时按接口约定标注“未知”；音乐样本仅检查可确定的字段。`subtitle_report.json` 保存最终同一语料的基线失败输入、字段差异、分组及耗时。

## 生成与标注

`build_recognition_corpus.py` 不导入解析器，只合并独立标注、去重后构造语义保持变体。旧 PT 快照不作为万条集合的真值。变体覆盖字幕标签位置、全角/半角括号、分辨率、发布组、修订集号、视频/字幕后缀、父目录和边缘空白；按标注名称与变换类别轮流取样，不按是否通过挑样本。

期望来自阅读标题、副标题和文件列表；文件系列按人工确认的名称和明确编号标注。只断言文本可确认的字段，不推断 TMDB ID、绝对集数映射或混合资源包的完整内容。英文名称沿用接口既有 title case 约定。

最终未压缩 JSONL 的 SHA-256：

`54998a82a28c768b1664d14504e8149682ce173c624d8c1072bcf04279ee8aff`

gzip 固定 `mtime=0`，重复生成的压缩字节相同。测试同时检查一万条数量、唯一输入、唯一 ID、期望非空和校验和。补齐站点标注前的初稿摘要保存在报告中；最终比较双方使用同一份最终语料，没有删除失败种子或用解析器结果生成期望。

## 本轮结果

| 入口/集合 | neo.2 | neo.3 |
| --- | ---: | ---: |
| 真实输入 | 1,425 / 1,447 | 1,447 / 1,447 |
| 格式变体 | 8,318 / 8,553 | 8,553 / 8,553 |
| Rust 完整万条 | 9,743 / 10,000 | 10,000 / 10,000 |
| 后端完整万条 | 9,743 / 10,000 | 10,000 / 10,000 |

通过表示该条全部已标注字段一致。257 条失败输入共享若干规则根因，不是 257 个不同 bug：

- 片名内部的 `【招架】`、`【Parry】` 等强调括号保持原文，不再拆成多个别名。
- 前置字幕语言标签在解析前排除，原始显示文本仍完整保留。
- 纯英文合集的裸 `10-bit`、双语片名后裸 `BDRip/WEB-DL` 等技术参数不再混入名称。
- 全角 `【MOVIE Fin】` 保持电影判定，明确技术区里的分辨率可从括号中补取。
- 文件名外侧普通/Unicode 空白不再影响后缀、文件和特典判定。

旧有修订集号、数字片名、合集范围、S00 特典、年度季号、字幕后缀、父目录继承、识别词及显式 ID 回归全部继续通过。

扩展 Python 全量：**12,049 passed、1 skipped、90 subtests passed**；Rust `cargo test --lib`：**28 passed**；Clippy、rustfmt 通过。后端全量：**12,934 passed、1 skipped**，全局网络守卫阻止真实出站。后端万条用例禁止 Python 回退。

## 性能与复测

macOS arm64、Python 3.12、release wheel。每组 3 轮，连续测 5 组，取每轮中位数；不同模式依次运行，计时不包含导入、语料读取和正确性断言。

| 入口 | neo.2 | neo.3 |
| --- | ---: | ---: |
| 单独 Rust，10,000 条 | 577.81 ms | 575.93 ms |
| 后端完整调用，10,000 条 | 700.71 ms | 700.95 ms |

后端纯 Python 路径：**2966.54 ms**；新版完整调用约为其 **4.23 倍**速度。相比 neo.2 性能基本持平。此处不包含网络、数据库、TMDB 匹配与下载耗时。完整分组、每组计时和基线失败 ID/字段差异保存在 `recognition_10k_report.json`；前两轮 1,196 条输入的历史结果仍在 `recognition_report.json`，不能混比。

```sh
.venv/bin/python scripts/build_recognition_corpus.py
.venv/bin/python -m pytest tests -q
cargo test --lib
.venv/bin/python scripts/benchmark_recognition_10k.py --output /tmp/recognition-10k.json
```

旧版可安装到独立目录，使用 `PYTHONPATH` 复放同一脚本。后端独立保存 `bt_pt_10k.jsonl.gz` 和清单，完整调用基准见后端 `scripts/benchmark_recognition_10k.py`。
